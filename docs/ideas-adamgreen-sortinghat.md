# Що взяти з adamgreen/SortingHat

Джерело: https://github.com/adamgreen/SortingHat (README, перелік файлів; код і ліцензію не читали).
Там nRF51 + Bluetooth (BLE) з телефону, звук 1-бітним ЦАП з wav на microSD, рот — сервопривід.
Ліцензія в README не вказана: код і креслення **не копіюємо**, беремо лише ідеї.
Їхні фрази — з фільмів (права Warner Bros.), нам не підходять, у нас свої 18 mp3.

## Корисне для нашої шапки
1. **Рот за гучністю звуку, а не за таблицею.** У них сервопривід іде за гучністю (обвідною)
   наступного шматка звуку. У нас таймінги рота — вручну в `firmware/hat/mouth.h`, і для кожної нової
   фрази їх треба підбирати. Можна:
   - у `gen_sounds.py` автоматично рахувати «увімк/вимк» з гучності mp3 і генерувати `mouth.h`
     (простіше, таблицю потім можна поправити руками);
   - або в прошивці рахувати гучність на льоту в аудіозадачі й керувати ШІМ мотора.
2. **Сервопривід замість мотора.** Сервопривід відкриває рот на потрібну величину, а не просто
   «відкрито / закрито», і рот рухається плавніше. На нашій платі без змін: сервопривід можна
   підключити до **J4** (+5V, DATA = GPIO7 через буфер 5 В, GND). Мотор на J5 тоді не потрібен.
3. **Сценарій сортування:** кілька випадкових фраз-«роздумів», потім оголошення факультету.
   У нас групи Старт → Грифіндор / Слизерин уже майже так; можна зробити одну кнопку «сортувати»:
   роздуми + випадковий або заданий факультет.
4. **Уроки з їхнього заліза:** сервопривід шумів у підсилювач LM386 по 5 В. У нас MAX98357A (цифровий
   вхід), діод і конденсатори на J5, тож ризик менший, але живлення сервоприводу варто брати
   товстим дротом прямо від клемника. Антену приймача тримати подалі від стінки шапки.

## Не підходить
BLE і телефон (у нас брелок 433 МГц), microSD (у нас звуки вбудовані), 1-бітний ЦАП (у нас MAX98357A).
